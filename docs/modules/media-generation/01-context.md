# 01 — Контекст и проблема

## Отправная точка

До этого модуля backend **ничего не генерировал, кроме текста и файлов сайта**. Изображения участвовали только как вход: inline base64-вложения для vision ([ADR-020](../../adr/ADR-020-inline-base64-attachments-mvp.md)). В каталоге инструментов tool-loop нет ни одного инструмента генерации медиа, и в API нет эндпоинта, который бы возвращал сгенерированную картинку или видео.

## Что усложняет задачу

**1. Время генерации несовместимо с синхронным HTTP.** Nano Banana отдаёт изображение за секунды, но Kling и Veo считают видео **минутами**. Синхронный эндпоинт означал бы HTTP-запрос, висящий 2–5 минут: его срежет reverse-proxy, iOS-таймаут и любая смена сети на мобильном устройстве. У fal ровно для этого случая есть queue API: `POST` возвращает `request_id` немедленно, статус и результат забираются отдельными `GET`.

**2. Пять моделей — пять разных входных схем, и fal отбивает лишние ключи.** У Veo нет `negative_prompt`, у Kling нет `resolution`, `num_images` есть только у image-моделей. Отдельно неприятно: имя поля с референсным изображением **не унифицировано** даже внутри одного вендора —

| модель | поле с картинкой |
|---|---|
| Nano Banana Pro / 2 (edit) | `image_urls` (список) |
| Kling Video 2.5 (image-to-video) | `image_url` |
| Kling Video V3 (image-to-video) | `start_image_url` |
| Veo 3.1 (image-to-video) | `image_url` |

Проксирование тела клиента к fal напрямую дало бы поток `422` на каждой второй комбинации модели и параметров.

**3. Prompt-only и «с картинкой» — это разные endpoint'ы.** `fal-ai/nano-banana-2` против `fal-ai/nano-banana-2/edit`, `…/text-to-video` против `…/image-to-video`. Выбор endpoint'а зависит от наличия картинки в запросе, то есть не может быть зашит в идентификатор модели.

**4. Каждый запуск стоит реальных денег,** причём Veo дороже Nano Banana на порядок. Значит нужна цена в кредитах — и она обязана быть серверной, иначе клиент сможет назначить себе бесплатную генерацию (тот же класс проблемы, что anti-tamper при покупке токенов, [ADR-015](../../adr/ADR-015-consumable-token-iap.md)).

**5. Генерация может провалиться после списания.** Провайдер отклоняет промт по content policy, падает, отменяет запуск. Списать и не вернуть — значит взять деньги за результат, которого нет.

## Чего модуль не делает

- Не встраивается в chat-оркестратор: генерация медиа не инструмент tool-loop, шагов в `chat_steps` не создаёт и от активного `LLM_PROVIDER` ([ADR-033](../../adr/ADR-033-llm-provider-abstraction.md)) не зависит.
- Не хранит и не проксирует сами файлы: клиент получает ссылки CDN провайдера (срок жизни ссылок — [Q-060-1](../../99-open-questions.md)).
- Не требует активной подписки: единственный гейт — баланс кредитов.
