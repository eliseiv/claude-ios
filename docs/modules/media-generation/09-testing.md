# 09 — Тест-план

Провайдер в тестах никогда не вызывается по сети: `httpx` подменяется **только внутри** `app.media_generation.fal_client` (surgical monkeypatch), поэтому собственный ASGI-клиент теста не затронут. БД — общий testcontainers PostgreSQL с применёнными миграциями.

## Почему наборы значений проверяются на сервере

Живой прогон 2026-08-04 показал: fal **не** валидирует enum на сабмите. Запрос с `resolution: "512x512"` (значения нет в схеме) получил `200`, request id и списание; статус дошёл до `COMPLETED`, а response URL навсегда отдавал `422 literal_error: Input should be '0.5K', '1K', '2K' or '4K'`. То же с `aspect_ratio: "auto"` у Veo text-to-video. То есть расхождение реестра со схемой провайдера проявляется не отказом сабмита, а **оплаченным запуском без результата** — отсюда и серверная валидация до списания, и требование держать наборы на уровне варианта.

`tests/e2e_live/verify_fal_catalog.py` (ручной, сетевой, вне `make ci`) сверяет каждый вариант реестра с опубликованной схемой fal: все форвардимые поля существуют наверху, все предлагаемые значения — подмножество upstream-enum'а, ни один форвардимый параметр не остался без набора значений. Прогонять при добавлении модели и периодически — схемы провайдера меняются без нашего участия.

## Integration — `tests/integration/test_media_generation_adr060.py`

Полный HTTP-путь через реальную JWT-аутентификацию, реальное списание/возврат и реальную персистентность.

**Каталог:** состав и порядок моделей, положительные цены, применение `MEDIA_MODEL_CREDITS`, отсутствие вендорных endpoint'ов и хоста очереди в ответе. Отдельно — форма `modes[]`: имена режимов по типу модели, порядок «сначала без картинки», `params` каждого режима, `baseDurationSeconds`/`supportsAudio`, и главное — одинаковый параметр с разными наборами значений в разных режимах (`aspectRatio` у Veo) и вовсе отсутствующий (`aspectRatio` у Kling image-to-video).

**Контракт сабмита:** URL очереди совпадает с endpoint'ом модели; тело — snake_case-поля модели; заголовок `Authorization: Key …` (не `Bearer`); наличие картинки переключает endpoint на `/edit` и `image-to-video`; `start_image_url` у Kling v3 против `image_url` у Kling 2.5. Параметры уходят только тем моделям, которые их принимают: `cfgScale` доезжает до Kling и отбрасывается у Veo, `seed` наоборот; `negativePrompt` принимают и Kling, и Veo.

**Валидация до списания** (`422`, ноль исходящих вызовов, баланс не изменился): неизвестная модель; video-модель на маршруте изображений; значение вне набора режима (`duration: "12s"` у Veo, `aspectRatio: "auto"` у Veo **text**-to-video — с картинкой то же значение принимается); параметр, которого у модели нет (`resolution` у Kling).

**Биллинг:** `202` списывает цену модели; масштабирование — `numImages: 4` списывает вчетверо, `duration: "15"` у Kling V3 втрое; `409 insufficient_credits` считается по **итоговой** цене (баланса хватает на 5 с, но не на 15 с) — без исходящего вызова; `502`/таймаут на сабмите → **списание откатилось** и строки задачи нет.

**Ошибки провайдера:** `401` → `503 media_generation_not_configured`; незаданный `FAL_API_KEY` → `503` без исходящего вызова; `422` → имя проблемного параметра доезжает до клиента.

**Опрос:** `IN_PROGRESS` → `running`; `COMPLETED` → `completed` + нормализованные `assets`; терминальная задача отдаётся из БД **без повторного вызова провайдера**; `FAILED` → `failed` + возврат кредитов, повторный опрос **не** возвращает второй раз; `COMPLETED` с пустым выводом → `failed` + возврат.

**Отказ уже принятого запуска:** `COMPLETED` + `422` из response URL (наблюдалось живьём с недостижимой картинкой) → `200` со `status: failed`, возвратом и текстом провайдера в `error`; повторный опрос не ходит наверх и не возвращает дважды. То же для `422` из status URL. В противоположность им `503` от провайдера при опросе → `502` клиенту, задача остаётся нетерминальной **и невозвращённой**, а следующий опрос доводит её до `completed`. Это верно для задачи **моложе** дедлайна; у задачи старше дедлайна тот же `503` даёт `200 failed` с возвратом ([§Дедлайн задачи](#integration--дедлайн-задачи-adr-105)).

**Листинг и изоляция:** newest-first, без опроса провайдера; фильтр `kind`; чужая задача → `404` и отсутствует в списке; несуществующая → `404`; `401` на JWT-маршрутах.

### Модерация UGC ([ADR-086](../../adr/ADR-086-ugc-moderation.md))

Клиент модерации подменяется на границе HTTP так же, как fal (surgical monkeypatch внутри модуля модерации) — по сети тесты не ходят.

**Пре-модерация (вход).**
- Отклонённый промпт → `422 content_policy_violation`; **баланс не изменился**, строки `media_jobs` нет, исходящего вызова к fal **не было**. Тот же набор проверок — для отклонённого `imageUrls`/`imageUrl` и для `POST /v1/media/uploads`.
- **Diff-тест порядка (обязателен):** перенос вызова модерации **после** `wallet.consume` обязан ронять тест — иначе спецификация «до списания» ничем не залочена и повторится дефект из BUG-006. Проверяется наблюдаемым фактом: при отклонении баланс равен исходному.
- Изображения, подставленные из `sourceJobId`, **не** уходят в модерацию (счётчик вызовов провайдера модерации = 1 на промпт, а не 1+N).
- Тело ошибки **не содержит** названий сработавших категорий (анти-эвейд), но задача, прошедшая проверку, несёт их в `moderation.categories` при `flagged`.

**Пост-модерация (выход).** Вердиктов в таблице исходов [ADR-086 §5](../../adr/ADR-086-ugc-moderation.md) **три** — `blocked`, `flagged`, `passed`; ниже названы все три плюс `unchecked` (см. «Контракт поля»), иначе прогон «перечень против тестов» показывает полноту при непроверенном штатном исходе.
- `COMPLETED` + вердикт `blocked` → `status: "failed"`, `assets: []`, `error: "content_policy_violation"`, `creditsRefunded: true`, `moderation.status: "blocked"`; повторный опрос **не** возвращает кредиты второй раз (ключ `media-refund:{jobId}`); media-ready push **не** отправлен.
- **Ассеты не достижимы:** после блокировки signed-URL download-роут по `index=0` отдаёт `404` (в `result` ассетов нет). Тест обязан падать, если реализация сохранит `assets` и лишь пометит вердикт.
- `COMPLETED` + `flagged` → `status: "completed"`, ассеты выданы, `creditsRefunded: false`, `moderation.status: "flagged"`.
- `COMPLETED` + `passed` (чистая задача) → `status: "completed"`, ассеты выданы, `creditsRefunded: false`, `moderation.status: "passed"`, `categories` пуст, `stage: "output"`. Это **штатный** исход, и без него зелёный набор не отличает «passed выставляется» от «поле осталось входным вердиктом». ⚠️ **На 2026-09-09 кейса на уровне задачи нет** — `tests/unit/test_moderation_adr086.py::test_clean_content_passes` проверяет вердикт **клиента модерации**, а не строку `media_jobs` и не ответ ручки; требование за `qa`.
- `kind=video` → omni-moderation на опросе не вызывается вовсе (счётчик вызовов провайдера = 0), `moderation.stage` остаётся `input`.
- **Видео-ветка вердикта `blocked` — чужим сигналом, а не omni-moderation ([ADR-086 §5](../../adr/ADR-086-ugc-moderation.md)):** терминальный отказ fal по его контент-политике классифицируется в `moderation.status: "blocked"`, `stage: "output"`, `provider: "fal"` — а не в безликий `failed`; обычный сбой провайдера (таймаут, недостижимая ссылка, пустой результат) в `blocked` **не** превращается. Узкий список маркеров покрыт парой `tests/unit/test_moderation_adr086.py::test_fal_content_refusal_is_recognised` и `…::test_ordinary_provider_failures_are_not_marked_blocked` — обе стороны предиката. ⚠️ **Кейса на уровне задачи (видео-задача с отказом fal → строка `media_jobs` с `blocked`/`output`/`fal` и возврат кредитов) на 2026-09-09 нет** — покрыт только предикат маркеров; требование за `qa`.
- **Метрика исходов.** `moderation_decisions_total{surface,stage,decision}` растёт в местах вызова, названных [ADR-086 §Наблюдаемость](../../adr/ADR-086-ugc-moderation.md) (`ChatOrchestrator.run`, `MediaGenerationService.submit` / `._advance` / `.upload_reference_image`); проверять **приращение серии в экспозиции `GET /metrics`**, а не факт объявления счётчика. ⚠️ **На 2026-09-09 кейса нет** — покрыта только сестринская `moderation_errors_total{reason="fail_open"}` (см. выше); объявленная, но ненаблюдённая метрика — ровно тот мёртвый артефакт, против которого написан абзац «Сквозная достижимость» ниже. Требование за `qa`.

**Отказ провайдера модерации.**
- На сабмите: `503 moderation_unavailable`, баланс не изменился, задачи нет (fail-closed).
- На опросе: задача остаётся non-terminal, `mark_completed` не выполнен, следующий опрос доводит её до терминала — **пока задача моложе дедлайна**; старше дедлайна — `failed` с возвратом без ассетов (кейс `moderation_unavailable` в [§Дедлайн задачи](#integration--дедлайн-задачи-adr-105)).
- `MODERATION_FAIL_OPEN=true` → операция проходит, вердикт `unchecked`, инкремент `moderation_errors_total{reason="fail_open"}`.
- `MODERATION_ENABLED=true` без ключа → `503 moderation_not_configured` **без** исходящего вызова.

**Контракт поля.**
- `moderation` присутствует и в `GET /v1/media/jobs/{jobId}`, и в **каждом** элементе `GET /v1/media/jobs` (тест обязан проверять именно ленту — иначе History снова покажет заблокированное).
- Строка с `moderation IS NULL` (эмуляция задачи, созданной до ADR-086) отдаётся как `{"status":"unchecked","stage":null,"categories":[],"checkedAt":null}` — **не** как `passed`.

**Сквозная достижимость (declared ≠ wired).** Удаление строки вызова модерации из `submit` либо из `_advance` обязано ронять хотя бы один тест. Тест, который сам конструирует вердикт и проверяет только маппинг в схему, покрытием цепи **не считается**.

## Integration — дедлайн задачи ([ADR-105](../../adr/ADR-105-provider-failure-input-shape-and-media-deadline.md))

Норма — [ADR-105 §B](../../adr/ADR-105-provider-failure-input-shape-and-media-deadline.md). Реализация раздела — `tests/integration/test_media_deadline_adr105.py` (коммит `cbed6ca`, 14 функций `test_`). Возраст задачи задаётся `created_at` строки (фиксированные часы теста), а не ожиданием; fal подменяется на границе httpx, как в остальном модуле. **Каждое наблюдение ниже гоняется ДВАЖДЫ — у задачи старше дедлайна и у задачи моложе дедлайна, — и обе половины пары обязательны:** половина (а) ловит недооценку (задача вечна), половина (б) — переоценку (живая задача провалена). Тест, проверяющий только одну половину, покрытием предиката не считается.

**Наблюдения (параметризация по ВСЕМ; перечень — снимок, наблюдение, появившееся позже, — та же строка):**

| Наблюдение опроса | `lastObservation` | (а) старше дедлайна | (б) моложе дедлайна |
|---|---|---|---|
| `status` → `500`, `502`, `504`, `402` (каждый отдельным кейсом) | `upstream_error` + `upstreamStatus` | `200`, `failed`, `error: "generation did not complete in time"`, `creditsRefunded: true`, баланс вырос на `creditsCharged` | `502`, строка `running`/`queued`, баланс не изменился |
| `status` → `429` | `upstream_error` + `upstreamStatus` | как выше | `429`, строка не терминальна |
| `status` → `401` (ключ отбит) | `upstream_error` + `upstreamStatus=401` | как выше | `503`, строка не терминальна |
| таймаут / обрыв соединения / битый JSON на `status` | `upstream_error`, без `upstreamStatus` | как выше | `502`, не терминальна |
| `status` → `IN_QUEUE`, `IN_PROGRESS` | `upstream_pending` | как выше | `200 running` |
| `status` → `COMPLETED`, `result` → `504` / таймаут | `upstream_error` | как выше | `502`, не терминальна |
| `COMPLETED` с ассетами, `kind=image`, провайдер модерации недоступен | `moderation_unavailable` | как выше, **`assets: []`**, signed-URL по `index=0` → `404` | не терминальна, ассеты не выданы |
| исключение в нормализации результата (подмена `_normalize_result`) | `internal_error` | как выше | исключение наверх, не терминальна |

**Последний шанс (вторая сторона (б)).** Задача старше дедлайна, опрос дал `COMPLETED` с ассетами → `completed`, ассеты выданы, `creditsRefunded: false`, события дедлайна **нет**; опрос дал `FAILED` → `failed` с **текстом fal**, а не текстом дедлайна. Кейс обязан падать при реализации «проверить возраст до опроса».

**Возврат ровно один раз:** повторный опрос задачи, закрытой по дедлайну, не ходит к fal и не даёт второй строки `media-refund:{jobId}`; два параллельных продвижения одной просроченной задачи дают ровно одну строку возврата.

**Сквозной путь согласователя (рабочий, не синтетика).** `reconcile_once` на реальной БД с просроченной задачей (`status` → `504`): задача `failed`, возврат, строка `request_logs` этой задачи — `failed`, `refunded=true`, `completed_at` проставлен (кейс обязан падать на прежней, до `cbed6ca`, сборке сервиса без `request_logs`). Задача моложе дедлайна в том же тике — не тронута. Пустой `FAL_API_KEY` — **двумя путями, и ни один из них не HTTP-ручка**: (1) `reconcile_once`; (2) сервисный `MediaGenerationService.get_job` (путь `GET`, но **ниже** роутера) — просроченная задача → `failed`, `lastObservation = not_configured`, **ни одного** исходящего вызова; молодая — не тронута (`get_job` поднимает прежний `MediaGenerationNotConfiguredError`). Через HTTP `GET /v1/media/jobs/{jobId}` этот исход **ненаблюдаем**: роутер `/v1/media` закрыт `require_media_generation_configured` и без ключа отвечает `503` до сервиса для любой задачи, просроченной тоже ([ADR-105 §B5](../../adr/ADR-105-provider-failure-input-shape-and-media-deadline.md), уточнение факта) — кейс «HTTP `GET` без ключа закрывает просроченную задачу» написать нельзя, и требовать его запрещено.

**Одна сборка сервиса ([ADR-105 §B6](../../adr/ADR-105-provider-failure-input-shape-and-media-deadline.md)).** Картинка, чью готовность обнаружил `reconcile_once` (`COMPLETED` + ассеты), проходит пост-модерацию: вердикт `blocked` → `failed` без ассетов, как на пути `GET`. Кейс обязан падать на прежнем, до `cbed6ca`, согласователе (он собирал сервис без `moderation` и выдавал ассеты непроверенными).

**Наблюдаемость (declared ≠ wired).** `media_generation_deadline_exceeded` с `jobId`, `model`, `ageSeconds`, `lastObservation` появляется в захваченном журнале на реальном пути (`GET` и `reconcile_once`); удаление строки эмиссии роняет тест. `lastObservation` проверяется **по предикату** — каждое значение своим кейсом из таблицы, и кейс падает при подмене значения соседним. `media_reconcile_job_error` несёт `exceptionClass`.

**Настройка.** `MEDIA_JOB_DEADLINE_SECONDS` не задан → `21600`; задан `60` → действует `60`; `0` и отрицательное → `21600` (правило нельзя выключить опечаткой).

**Diff-тест регрессии (обязателен).** Откат ветки дедлайна в `_advance` роняет все половины (а); откат «последнего шанса» (проверка возраста до опроса) роняет кейс `COMPLETED` старше дедлайна; снятие `request_logs`/`moderation` со сборки согласователя роняет два кейса сквозного пути.

## Integration — транспорт через прокси ([ADR-108](../../adr/ADR-108-media-generation-via-proxy.md))

Норма — [ADR-108](../../adr/ADR-108-media-generation-via-proxy.md); реализация раздела — `tests/unit/test_media_proxy_units_adr108.py`, `tests/integration/test_media_proxy_adr108.py`, `tests/integration/test_migration_0038_media_jobs_proxy_adr108.py`. Прокси подменяется на границе httpx (фейк `POST {PROXY_BASE}/api/v1/tasks`), колбэк подаётся настоящим HTTP-запросом на `POST /v1/media/webhooks/proxy/{jobId}` с токеном, вычисленным от `jobId`. Каждый пункт — отдельный кейс; перечень — снимок, элемент нормы ADR-108, здесь не названный, — тот же кейс.

**Выбор транспорта (§1):** `PROXY_API_KEY` + `SERVICE_DOMAIN` → сабмит в прокси, прямой fal не вызывается; `PROXY_API_KEY` пуст, `FAL_API_KEY` задан → прямой fal как сегодня, строка `provider = ''`; `PROXY_API_KEY` задан, `SERVICE_DOMAIN` пуст, `FAL_API_KEY` пуст → `503 media_generation_not_configured` **до** списания; оба пусты → `503` на `/v1/media/*`, media-строк нет в `GET /v1/models`. С прокси и без `FAL_API_KEY`: `POST /v1/media/uploads` и i2v с fal-хостом стартового кадра → `503` до списания.

**Откат списания на chat-tool (§3.1) — обе стороны предиката, каждый пункт отдельным кейсом, у каждого — своя мутация:**

| Кейс | Наблюдение (сторона предиката) | Ожидание | Мутация, обязанная уронить ИМЕННО этот кейс |
|---|---|---|---|
| транспорт `502` после `consume` (`UpstreamError`) | (а) отказ | ход не падает, ошибка инструмента; баланс не изменился; строки `media-gen:{jobId}` нет; `media_jobs` не создана | снять `savepoint()` вокруг `consume → транспорт → INSERT` в `submit` |
| `422` маршрута fal после `consume` (`ValidationFailedError`) | (а) отказ | то же | то же |
| `401`/`403` прокси после `consume` (`MediaGenerationNotConfiguredError`) | (а) отказ | то же | то же |
| `409 insufficient_credits` внутри `consume` ([TD-048](../../100-known-tech-debt.md)) | (а) отказ | то же | то же |
| `submit_custom` (features), транспорт `502` после `consume` | (а) отказ | то же | снять `savepoint()` в `submit_custom` (кейсы `submit` при этом зелёные) |
| успешный сабмит из tool-loop | (б) успех | баланс уменьшен ровно на `creditsCharged`; строка `media-gen:{jobId}` и задача есть | откат savepoint на успешном пути (например, `raise` после `INSERT` внутри блока с перехватом снаружи) |
| REST `POST /v1/media/images`, транспорт `502` | (б) контроль: прежнее поведение REST | `502`, баланс не изменился, задачи нет | — (кейс существует до ADR-108 и остаётся зелёным при снятии savepoint: REST откатывает весь запрос) |

Последняя строка намеренно НЕ зависит от вложенной транзакции — она доказывает, что откат chat-tool кейсов вызван именно savepoint, а не общим откатом запроса.

**Себестоимость (§8) — обе стороны:** (а) задача `provider='fal'` и `provider='sosana'`, колбэк с `vendor_price` (`completed`, `failed`, `no_usable_asset` — отдельными кейсами) → `provider_cost_usd = vendor_price`, `vendor_price` записан, CRM-выборка (`crm_service`/`crm_costs`) показывает реальную цену; (б) задача `provider='kie'` с тем же колбэком → `vendor_price` записан, `provider_cost_usd` = **оценка сабмита** (замены нет); колбэк с `vendor_price: null` → `provider_cost_usd` = оценка, не `NULL`; колбэк, где цена есть только в `data.creditsConsumed`, → `vendor_price` **пуст**, оценка не тронута. Мутации: снять замену — роняет (а), не трогая (б); снять ограничение по сервису (замена для всех) — роняет кейс `kie`; вернуть `creditsConsumed` в парсер — роняет кейс `creditsConsumed`.

**SQL `NULL` у `pending_result` ([TD-061](../../100-known-tech-debt.md)):** после вставки proxy-задачи и после терминала `pending_result IS NULL` истинно; незавершённая proxy-задача без колбэка старше часа учитывается `media_proxy_jobs_awaiting_callback`.

**Бюджет сабмита (§3.3):** таймаут прокси на первом маршруте → `502`, второй маршрут **не** вызывается, списания нет; `5xx` на первом → вызывается второй. Прокси не вернул id → `fal_request_id = ''`.

**Сабмит (§2, §3):** тело запроса к прокси (`service`, `endpoint = https://queue.fal.run/<endpoint варианта>`, `method`, `payload`, `callbackUrl`), `Authorization: Bearer`, ключа вендора в теле нет; `payload` fal-маршрута **побайтно равен** сегодняшнему payload fal для каждой из пяти моделей в обоих режимах (параметризация, эталон — `build_fal_input` на тех же значениях). `creditsCharged` и строка `media-gen:{jobId}` совпадают с сегодняшними для каждой ячейки тарифа (эталон — `run_price()`); цена не зависит от выбранного маршрута. Строка: `provider`, `status_url = ''`, `response_url = ''`, `fal_request_id` = id прокси.

**Маршрутизация (§2.1) — обе стороны предиката:** (а) при непустом `MEDIA_RESULT_HOST_SUFFIXES`, `nano-banana-2` `2K`, `numImages=1`, без `seed`/`outputFormat` → первый маршрут `sosana`; (б) каждое нарушение условия отдельным кейсом → единственный маршрут `fal`: пустой `MEDIA_RESULT_HOST_SUFFIXES` (и тогда же — колбэк с URL relay-хоста `relay2.mediabackender.com` → `no_usable_asset`, возврат; с `MEDIA_RESULT_HOST_SUFFIXES=.mediabackender.com` тот же колбэк → `completed`); `numImages=2`; `0.5K`; `seed`; `outputFormat=webp` (и `png` у sosana); `aspectRatio=8:1`; `aspectRatio` не задан (вендору ушло бы `"auto"`). Видео-модели и features — только `fal`. Оверрайд `MEDIA_VENDOR_PRICES`, делающий fal дешевле, ставит fal **первым**; `422` fal в этом случае → `422 validation_error`, `sosana`/`kie` не вызываются.

**Ошибки сабмита (§3.3), каждая строка таблицы отдельным кейсом:** откат на следующий маршрут на `429`/`5xx`/`402`/таймаут/`400` без валидации; `422` у `sosana` → откат на `fal`; `422` у `fal` → `422 validation_error`; `401`/`403` → `503` без отката; маршруты исчерпаны → `502`/`429`. **Во всех отказах** — строки `media-gen:{jobId}` в ledger нет и `media_jobs` не создана.

**Вебхук (§4) — порядок проверок нормативен:** неверный/пустой токен → `401` без чтения БД (при несуществующем `jobId` тоже `401`, а не `404`); тело-массив → `422`; нет строки → `404`; legacy-строка (`provider = ''`) с валидным токеном → `404`; терминальная → `200`, строка не меняется, второй строки `media-refund` нет; `pending` → `running`; `failed` → `failed`, `creditsRefunded: true`, текст вендора в `error`; `completed` (форма fal с `content_type`/`file_name`) → `completed`, `contentType`/`fileName` сохранены, `vendor_price` записан; `completed` с хостом вне allowlist → `failed`, `"generation produced no output"`, возврат; повторный `completed` → без второго push. **Шаг 0 (результат уже получен), отдельными кейсами на задаче с записанным `pending_result` (модерация была недоступна):** колбэк `failed` → задача не `failed`, возврата нет, `pending_result` не изменён, `outcome = result_already_received`; колбэк `pending` → то же; колбэк `completed` с ДРУГИМ URL → `pending_result` не перезаписан, при доступной модерации задача `completed` с ассетом ПЕРВОГО колбэка. Кейсы обязаны падать на реализации, применяющей `failed` поверх записанного результата или перезаписывающей `pending_result`. Ручки нет в OpenAPI.

**Общий путь завершения (§5) — сквозной, не синтетика:** `POST /v1/media/images` → колбэк `completed` → `GET /v1/media/jobs/{jobId}` отдаёт `completed` с signed URL; строка `request_logs` закрыта; push отправлен один раз; `blocked` пост-модерацией → `failed`, `assets: []`, возврат, push нет. Модерация недоступна в колбэке → ответ `200`, задача **нетерминальна в прежнем статусе** (отдельными кейсами: была `queued` → осталась `queued`; была `running` → осталась `running`), `pending_result` записан, **частичных записей handler нет**; следующий `GET` при доступной модерации → `completed` (кейс обязан падать на реализации без `pending_result` и на реализации без `SAVEPOINT`). Подготовка аватара (`visible_in_history=false`) через колбэк → байты сохранены в `user_avatars`.

**Дедлайн (§6) — обе половины:** proxy-задача старше дедлайна без колбэка → `failed`, `lastObservation = webhook_pending`, **ни одного** исходящего вызова; моложе → `running`, не тронута; с `pending_result` и старше дедлайна при доступной модерации → `completed`, а не `failed`. Колбэк после закрытия дедлайном → `200`, `duplicate_terminal`, возврат не дублируется. Колбэк `completed` и закрытие дедлайном одной задачи параллельно → ровно один терминал и не более одной строки `media-refund`. Legacy-задача (`provider = ''`) — опрос fal, как в разделе дедлайна выше.

**Согласователь (§6):** строка proxy-задачи, захваченная параллельной транзакцией, в тике пропускается (`SKIP LOCKED`) и доводится следующим; тик не ждёт захвата. proxy-задачи в выборке без исходящих вызовов; при пустом `FAL_API_KEY` молодая legacy-задача не выбирается, молодая proxy-задача с `pending_result` выбирается и доводится.

**Наблюдаемость (declared ≠ wired):** каждое значение `media_webhook_outcome.outcome` — своим кейсом на реальном пути (`completed` — только при итоговом `completed`; `blocked` пост-модерацией в колбэке → `completion_failed`); фильтр access-лога (`AccessLogQueryRedactionFilter`, пишет `qa`): строка `uvicorn.access` колбэка не содержит `token=` (а), строка `uvicorn.access` любого ДРУГОГО пути с query сохраняет query как есть (б), снятие фильтра с логгера роняет (а); `media_proxy_jobs_awaiting_callback` после `reconcile_once` на реальной БД присутствует в экспозиции `/metrics` и считает proxy-задачу без колбэка старше часа, но **не** считает задачу моложе часа, задачу с `pending_result` и legacy-строку (обе стороны предиката [ADR-108 §10](../../adr/ADR-108-media-generation-via-proxy.md)); удаление строки эмиссии роняет кейс; в захваченных логах нет значений `PROXY_API_KEY`, `PROXY_WEBHOOK_SECRET` и `token`.

**Diff-тест регрессии (обязателен):** откат выбора транспорта на прямой fal роняет кейсы сабмита; снятие проверки токена роняет кейс `401`; снятие `FOR UPDATE` роняет кейс параллельного терминала; откат условий §2.1 роняет кейсы (б).

## Integration — своё хранение результатов ([ADR-109](../../adr/ADR-109-media-asset-local-storage-30d.md))

Норма — [ADR-109](../../adr/ADR-109-media-asset-local-storage-30d.md); **код в `main` (`f90d871`), выкачен (CI `36015691825` на `48f9018`, джоб `ssh deploy` — `success`); автотесты — `tests/integration/test_media_asset_store_adr109.py`, 31 функция `test_adr109*` на 2026-09-24; прогон и покрытие не измерены, `qa` пишет ещё**. Источник байтов подменяется на границе httpx, каталог хранения — временный каталог теста. Каждый пункт — отдельный кейс; у каждого — мутация, роняющая ИМЕННО его (выбирает `qa`, по одной на инвариант).

**Сквозной путь (обязателен, иначе цепь не покрыта):** хранение включено → `POST` → завершение (колбэк прокси и, отдельным кейсом, опрос legacy) → тик цикла → строка `stored`, файл на диске → `GET` signed URL отдаёт байты **с диска** при источнике, который теперь отвечает `404` (`source=local` в `media_asset_download_total`). Тест, который сам пишет файл или ставит `stored` в БД, покрытием цепи не считается.

**Путь завершения (§2):** хранение включено → после `completed` `asset_store_status='pending'`, `assets_expire_at = завершение + срок`; хранение выключено → `''` и `NULL`; `failed` и заблокированный модерацией результат → `''`. Исключение в цикле сохранения не меняет ни статус задачи, ни кредиты.

**Исходы попытки (§3) — по кейсу на строку таблицы:** `stored`; `retry` (5xx/таймаут → `attempts+1`, пауза) и `exhausted` на 12-й; `gone` (404/410 → `failed`); `too_large` (по `Content-Length` и, отдельным кейсом, без него — по прочитанному; частичный файл удалён); `host_rejected`; `deferred_low_disk` до запроса (по `MEDIA_ASSET_MAX_BYTES`) и отдельно по `Content-Length` ответа (попытка не тратится, строка `pending`, меняется только `next_attempt_at`); `deferred_unavailable` (каталога нет). **Порядок без сети:** при запрещённом хосте и при нехватке места фейк источника НЕ получает ни одного запроса (счётчик вызовов фейка = 0). Против переоценки: `deferred_*` НЕ переводят строку в `failed`; против недооценки: `gone`/`too_large` НЕ ретраятся.

**Идемпотентность и атомарность:** два тика подряд по одной строке → один файл, тождественное содержимое; задача из двух ассетов при отказе второго → строка не `stored`, download идёт к источнику; строка удалена во время скачивания → условный `UPDATE` не находит строки, файл вычищается как сирота. Два исполнителя одновременно → работает один.

**Download-роут (§5):** своя копия в сроке → байты с диска, `Range` → `206` + `Content-Range`, `HEAD` без тела, набор заголовков как у пути источника, `Content-Type` из `stored_assets`; **невыполнимый `Range` → `404`** (не `416`), `If-None-Match` с совпадающим `ETag` → полный `200` (не `304`); срок прошёл → путь источника; хранение включено, корень с маркером доступен, `stored`, а файла нет → путь источника, строка `missing`, повторная отдача WARNING не пишет; **корень недоступен (каталога нет / маркера `.media-assets-root` нет) при десятке строк `stored` → путь источника, WARNING `media_asset_storage_unavailable`, ни одна строка не меняет статус** (мутация «убрать проверку маркера» обязана уронить кейс); строка `missing`, чей файл снова положен в каталог, → байты с диска и статус `stored`; иная ошибка чтения → путь источника без смены статуса; **хранение выключено при строке `stored` → путь источника, диск не читается, строка остаётся `stored`, `local_missing` не растёт**; битый токен → `401` без чтения диска; форма `assets[].url` в ответе задачи не меняется.

**Gauge на нескольких воркерах (§9):** два процесса (или два экземпляра цикла с общей БД и каталогом), право исполнения — у одного; оба после тика публикуют одинаковые `media_asset_storage_free_bytes`, `media_asset_store_pending`, `media_asset_store_failed`, `media_asset_missing`, равные значениям в БД/ФС. Мутация «Gauge ставится после получения права исполнения» обязана уронить кейс (у второго процесса `0`).

**Очистка (§6), обе стороны:** (а) истёкшая строка → каталог удалён, `expired`; сирота старше часа → удалён; брошенный tmp старше часа → удалён; (б) `stored` в сроке — не удаляется, в том числе при нехватке места; `missing` по сроку → `expired`; свежая сирота (моложе часа) — не удаляется; **законное массовое удаление** (удалён пользователь с 500 задачами, тождество базы совпало) → все его подкаталоги удалены за один тик, `media_asset_cleanup_blocked = 0`; **чужая или пустая база на маленьком инстансе** (≤ 100 подкаталогов, `pg_system_identifier` маркера ≠ `system_identifier` базы) → ни один подкаталог не удалён, шаги 1–2 и сохранение работают, WARNING `media_asset_cleanup_aborted` (`identity_mismatch`), Gauge `= 1` в каждом воркере; маркер без строки идентификатора → то же с `identity_absent`; перезапись маркера верным значением → следующий тик удаляет сирот, Gauge `= 0`; повтор очистки после падения между «удалить файлы» и «обновить строку» — тождествен.

**Миграция:** upgrade/downgrade, single head, существующие строки получают `''`/`0`/`NULL`, `CHECK` отвергает чужое значение, `stored_assets` без значения — SQL `NULL`.

- Оверлей ячейки → `creditsCharged` равен ячейке; соседние ячейки **не** меняются (поячеечность).
- `prices[]` в `GET /v1/media/models` совпадает со списанием для каждой комбинации.
- **Численная модель по ВСЕМ комбинациям всех трёх видео-моделей (46 ячеек):** на дефолтной таблице выведенная тройка равна значениям реестра **поэлементно** (`kling-video` → `credits=14`, `audioMultiplier=null`; `kling-video-v3` → `23` / `1.5`; `veo-3.1` → `32` / `{720p:1,1080p:1,4k:2}` / `2`) и воспроизводит **каждую** ячейку; `media_price_legacy_overquote` равна **нулю**.
- Кейс обязан **падать** при реализации «максимум отношений ячеек»: на `kling-video-v3` она даёт `1.5217` вместо `1.5` и расходится в 10 из 26 комбинаций **на дефолтах**.
- Непредставимая таблица (поднята одна ячейка): перебором всех комбинаций — **ни одного занижения**; эмитится `media_price_legacy_overquote`. Кейс падает при замене округления вверх на вниз.
- Модель без измерения: `resolutionMultipliers`/`audioMultiplier` = **`null`**, а не `1` (ассерт на `null`).
- Цена **никогда** не берётся из тела запроса: подмена `credits`-подобного поля игнорируется (`extra="forbid"`).
