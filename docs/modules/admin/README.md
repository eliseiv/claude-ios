# Module: Admin

- Статус: Реализован
- Ответственность: операторские/саппорт-действия над аккаунтами под изолированной admin-авторизацией. Начисление кредитов (`wallet/grant`), read-only просмотр кошелька, ручная активация/продление подписки (`subscription/grant`, [ADR-048](../../adr/ADR-048-admin-subscription-grant.md)), read-only периодная разбивка расходов на провайдеров для CRM (`costs/daily`, [ADR-092](../../adr/ADR-092-crm-daily-costs-endpoint.md)).

> **Про CRM-подмножество `/v1/admin/*`.** Эндпоинты панели broad-crm (`GET /v1/admin/users`, карточка, оплаты, запросы, `products`, `stats`, гранты токенов/подписки) живут в `src/app/api_gateway/routers/crm_admin.py` под тем же `require_admin`, но их контракты в этих module-docs **не описаны** — первоисточник для них [ADR-077](../../adr/ADR-077-crm-request-logs.md) / [ADR-078](../../adr/ADR-078-crm-request-history-derived-from-domain.md) / [ADR-079](../../adr/ADR-079-crm-provider-cost-duration-payments.md) и [08-api-documentation §CRM Admin API](../../08-api-documentation.md#crm-admin-api-история-запросов-adr-077-модель-чтения--adr-078). Исключение — `costs/daily` ([ADR-092](../../adr/ADR-092-crm-daily-costs-endpoint.md)): его контракт описан здесь целиком, в [02-api-contracts.md](02-api-contracts.md#get-v1admincostsdaily--периодная-разбивка-расходов-adr-092).

## DoD
- `POST /v1/admin/wallet/grant` начисляет кредиты через существующий `WalletService.grant()`, идемпотентно по `idempotencyKey`, с обязательным `reason`; ответ `{newBalance, ledgerTxId, idempotentReplay}`.
- `GET /v1/admin/wallet/{userId}` отдаёт баланс + последние ledger-транзакции (read-only).
- `POST /v1/admin/subscription/grant` ([ADR-048](../../adr/ADR-048-admin-subscription-grant.md)) активирует/продлевает подписку (upsert `subscriptions` `status='active'`, `plan`, `expires_at`) **без** StoreKit-транзакции; срок = ровно одно из `expiresAt` (tz-aware, `>now()`) / `days` (>0); опц. начисление кредитов в том же запросе (дефолт `SUBSCRIPTION_CREDITS_PER_PERIOD`, явный `0` = без начисления) через `WalletService.grant`, идемпотентно по `idempotencyKey`; `404 user_not_found`; всё в одной транзакции; audit `admin_subscription_grant`.
- `GET /v1/admin/costs/daily` ([ADR-092](../../adr/ADR-092-crm-daily-costs-endpoint.md)) отдаёт клетки `(день, провайдер)` за период (UTC, обе границы включительно, ≤ 92 дня, порядок `date ASC, provider ASC`): `requests` = число **оплаченных обращений к провайдеру**, `spend_usd`/`tokens` по закупочному прайсу [ADR-079](../../adr/ADR-079-crm-provider-cost-duration-payments.md) (`Fal` → `tokens = 0.0`); `null` — только когда не оценён ни один вызов клетки, «нет строки» — измеренный ноль; неатрибутируемый вызов (`usage` есть, имени модели нет) отдаётся отдельной клеткой с сырым ключом `"Unknown"`; `400` на невалидном периоде (в т.ч. на `2026-8-1` — форма строго 4/2/2 цифры), `422` на схеме, `404` **не возникает**. Имена пути/параметров/полей заморожены контрактом CRM v1.3 и из этого репозитория не меняются.
- Авторизация — изолированный admin-секрет ([ADR-009](../../adr/ADR-009-admin-token-auth.md)) в заголовке `X-Admin-Key` (CRM) или легаси `X-Admin-Token`, отдельная зависимость `require_admin` (нет заголовка → `403`, неверное значение → `401`), не пересекается с пользовательским JWT, не запускает provisioning, не трогает trial.
- Аудит-событие `admin_grant` (actor=admin, reason, без секрета). Отдельный rate limit, strict validation, size-лимиты.
