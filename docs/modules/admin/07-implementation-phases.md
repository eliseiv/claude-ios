# Admin — Implementation Phases

| Phase | Задача | Зависит от |
|---|---|---|
| ADM-1 | Config: `ADMIN_API_SECRET` (+ опц. `ADMIN_API_SECRET_PREV`), `ADMIN_RATE_LIMIT_PER_MIN` (дефолт 10) в pydantic-settings. Добавить `X-Admin-Token` в redaction allowlist. | — |
| ADM-2 | Зависимость `require_admin` (constant-time compare обоих секретов, `401` при несовпадении; **без** provisioning/trial/`get_current_user`). | ADM-1 |
| ADM-3 | Роутер `api_gateway/routers/admin.py` (`/v1/admin/*`) + отдельный rate limit per source IP + size-лимит ≤ 8 KB. | ADM-2 |
| ADM-4 | `POST /v1/admin/wallet/grant`: Pydantic-схема (`extra='forbid'`, `amount>0`, `reason` непустой); проверка существования `users(userId)` → `404`; вызов `WalletService.grant`; audit `admin_grant`; ответ `{newBalance, ledgerTxId, idempotentReplay}`. | ADM-3, Wallet |
| ADM-5 | `GET /v1/admin/wallet/{userId}`: проверка существования → `404`; `WalletService.get_wallet_view`. | ADM-3, Wallet |
| ADM-6 | Audit: новый `eventType=admin_grant` в каталоге Audit; убедиться, что секрет не логируется. | ADM-4, Audit |
| ADM-7 | Метрика `admin_grant_total{result=success|conflict|not_found}` (observability). | ADM-4 |
| ADM-8 | `POST /v1/admin/subscription/grant` ([ADR-048](../../adr/ADR-048-admin-subscription-grant.md)): Pydantic-схема `AdminSubscriptionGrantRequest` (`extra='forbid'`; **XOR-валидатор** «ровно одно из `expiresAt`/`days`»; `expiresAt` — tz-aware **и** строго `> now()`; `days>0`; `credits≥0`; `plan` дефолт `manual_grant`); `AdminService.grant_subscription` — проверка `users(userId)` → `404`, **ORM-upsert `Subscription`** (`status='active'`, `plan`, `expires_at`) без StoreKit-verify, опц. `WalletService.grant` с **namespace-ключом** `admin-sub-grant:{idempotencyKey}` (default `credits`=`SUBSCRIPTION_CREDITS_PER_PERIOD`, `credits=0`→без начисления, `409` на тот же ключ+другой `credits`); audit `admin_subscription_grant` (actor=admin, без секрета); всё в одной транзакции; ответ `{status, expiresAt, plan, creditsGranted, newBalance?, ledgerTxId?, idempotentReplay?}`. Новый `eventType=admin_subscription_grant` в каталоге Audit. Опц. метрика `admin_subscription_grant_total{result=success|conflict|not_found}`. Без миграции. | ADM-2, ADM-3, Wallet |
| ADM-9 ✅ | `GET /v1/admin/costs/daily` ([ADR-092](../../adr/ADR-092-crm-daily-costs-endpoint.md)): роут в CRM-роутере (`_parse_date` → `400` на формате / `date_from > date_to` / периоде > 92 дней; `limit` 1…1000, `offset` ≥ 0 → `422` штатным конвейером FastAPI; `404` не возникает); агрегатор `src/app/admin/crm_costs.py` — два SQL (сырые суммы счётчиков `chat_steps` по (день, модель); `media_jobs` по (день, модель, кредиты, число ассетов)) + аккумулятор `_Slot` (`spend_usd`/`tokens` стартуют с `None`, `requests` — с нуля); **цена применяется вне SQL**, модулем `app.pricing.provider_prices`; восстановление media-цены — переиспользованием `CrmAdminService._provider_cost`, не копией правил [ADR-079 §2](../../adr/ADR-079-crm-provider-cost-duration-payments.md); схемы `CrmDailyCostItem`/`CrmDailyCostListResponse` (имена полей **заморожены** контрактом CRM v1.3); пагинация в памяти, `total` = число клеток за весь период; индекс `ix_steps_created_at` + миграция `0029_steps_created_idx`. **Мутаций и audit нет.** | ADM-2, ADM-3, [ADR-079](../../adr/ADR-079-crm-provider-cost-duration-payments.md) |
| ADM-10 ✅ | **Закрыто ([ADR-092 §6](../../adr/ADR-092-crm-daily-costs-endpoint.md)).** Неатрибутируемый вызов (`usage` есть, `model` не строка) отдаётся клеткой с сырым ключом `PROVIDER_UNKNOWN = "Unknown"` (`src/app/pricing/provider_prices.py:129`, экспорт фасада `src/app/pricing/__init__.py:8,24`) — константа рядом с `PROVIDER_OPENAI`/`PROVIDER_ANTHROPIC`/`PROVIDER_FAL` (`provider_prices.py:122-124`): `slot.requests += calls`, `spend_usd`/`tokens` **не трогаются** и остаются `null` (`src/app/admin/crm_costs.py:198-210`). Шаг **без** `usage` в счёт **не входит** — фильтр `AND s.usage IS NOT NULL` (`crm_costs.py:111`) сохранён: это шаг-объявление медиа-визарда (`src/app/chat/orchestrator.py:1457-1465`), а не вызов LLM. | ADM-9 |
| ADM-11 ✅ | **Форма даты ужесточена ([ADR-092 §5](../../adr/ADR-092-crm-daily-costs-endpoint.md)).** `strptime("%Y-%m-%d")` не проверяет ширину компонент и принимал `2026-8-1` ⇒ эндпоинт отдавал `200` вместо нормативного `400`. Перед разбором добавлен `_ISO_DATE_RE = re.compile(r"[0-9]{4}-[0-9]{2}-[0-9]{2}")` (`src/app/api_gateway/routers/crm_admin.py:66`, `fullmatch` — `:77-78`); `[0-9]`, а не `\d`, — `\d` матчит не-ASCII цифры, которые `strptime` тоже принимает. `strptime` **сохранён** (`:79-84`): он ловит календарную невалидность (`2026-02-30`). Ужесточение изолировано `costs/daily` — `_parse_date` (`:69-84`) вызывается только оттуда (`:208-209`), а `/stats` и `/users` разбирают границы функцией `_parse_dt` (`:42-49`), которая не тронута. | ADM-9 |
