| ADM-8 | `POST /v1/admin/subscription/grant` ([ADR-048](../../adr/ADR-048-admin-subscription-grant.md)): Pydantic-схема `AdminSubscriptionGrantRequest` (`extra='forbid'`; **XOR-валидатор** «ровно одно из `expiresAt`/`days`»; `expiresAt` — tz-aware **и** строго `> now()`; `days>0`; `credits≥0`; `plan` дефолт `manual_grant`); `AdminService.grant_subscription` — проверка `users(userId)` → `404`, **ORM-upsert `Subscription`** (`status='active'`, `plan`, `expires_at`) без StoreKit-verify, опц. `WalletService.grant` с **namespace-ключом** `admin-sub-grant:{idempotencyKey}` (default `credits`=`SUBSCRIPTION_CREDITS_PER_PERIOD`, `credits=0`→без начисления, `409` на тот же ключ+другой `credits`); audit `admin_subscription_grant` (actor=admin, без секрета); всё в одной транзакции; ответ `{status, expiresAt, plan, creditsGranted, newBalance?, ledgerTxId?, idempotentReplay?}`. Новый `eventType=admin_subscription_grant` в каталоге Audit. Опц. метрика `admin_subscription_grant_total{result=success|conflict|not_found}`. Без миграции. | ADM-2, ADM-3, Wallet |
| ADM-9 ✅ | `GET /v1/admin/costs/daily` ([ADR-092](../../adr/ADR-092-crm-daily-costs-endpoint.md)): роут в CRM-роутере (`_parse_date` → `400` на формате / `date_from > date_to` / периоде > 92 дней; `limit` 1…1000, `offset` ≥ 0 → `422` штатным конвейером FastAPI; `404` не возникает); агрегатор `src/app/admin/crm_costs.py` — два SQL (сырые суммы счётчиков `chat_steps` по (день, модель); `media_jobs` по (день, модель, кредиты, число ассетов)) + аккумулятор `_Slot` (`spend_usd`/`tokens` стартуют с `None`, `requests` — с нуля); **цена применяется вне SQL**, модулем `app.pricing.provider_prices`; восстановление media-цены — переиспользованием `CrmAdminService._provider_cost`, не копией правил [ADR-079 §2](../../adr/ADR-079-crm-provider-cost-duration-payments.md); схемы `CrmDailyCostItem`/`CrmDailyCostListResponse` (имена полей **заморожены** контрактом CRM v1.3); пагинация в памяти, `total` = число клеток за весь период; индекс `ix_steps_created_at` + миграция `0029_steps_created_idx`. **Мутаций и audit нет.** | ADM-2, ADM-3, [ADR-079](../../adr/ADR-079-crm-provider-cost-duration-payments.md) |
| ADM-10 ✅ | **Закрыто ([ADR-092 §6](../../adr/ADR-092-crm-daily-costs-endpoint.md)).** Неатрибутируемый вызов (`usage` есть, `model` не строка) отдаётся клеткой с сырым ключом `PROVIDER_UNKNOWN = "Unknown"` (`src/app/pricing/provider_prices.py:129`, экспорт фасада `src/app/pricing/__init__.py:8,24`) — константа рядом с `PROVIDER_OPENAI`/`PROVIDER_ANTHROPIC`/`PROVIDER_FAL` (`provider_prices.py:122-124`): `slot.requests += calls`, `spend_usd`/`tokens` **не трогаются** и остаются `null` (`src/app/admin/crm_costs.py:198-210`). Шаг **без** `usage` в счёт **не входит** — фильтр `AND s.usage IS NOT NULL` (`crm_costs.py:111`) сохранён: это шаг-объявление медиа-визарда (`ChatOrchestrator._handle_media_selection`, `src/app/chat/orchestrator.py` — путь «продолжить или завершить визард **без вызова LLM**», поэтому `usage` у шага нет), а не вызов LLM. | ADM-9 |
| ADM-11 ✅ | **Форма даты ужесточена ([ADR-092 §5](../../adr/ADR-092-crm-daily-costs-endpoint.md)).** `strptime("%Y-%m-%d")` не проверяет ширину компонент и принимал `2026-8-1` ⇒ эндпоинт отдавал `200` вместо нормативного `400`. Перед разбором добавлен `_ISO_DATE_RE = re.compile(r"[0-9]{4}-[0-9]{2}-[0-9]{2}")` (`src/app/api_gateway/routers/crm_admin.py`), его `fullmatch` стоит в `_parse_date` **до** `strptime`; `[0-9]`, а не `\d`, — `\d` матчит не-ASCII цифры, которые `strptime` тоже принимает. `strptime` в `_parse_date` **сохранён**: он ловит календарную невалидность (`2026-02-30`). Ужесточение изолировано `costs/daily` — `_parse_date` вызывается только из `crm_daily_costs`, а `/stats` и `/users` разбирают границы функцией `_parse_dt` (там же), которая не тронута. | ADM-9 |
| ADM-12 | **Слой оверлеев** ([ADR-099 §2](../../adr/ADR-099-crm-admin-economics-and-instance-settings.md)): миграция `0033_admin_economics` (три таблицы + ослабление `NOT NULL` у `audit_logs.user_id`, expand-only, **без backfill**), пакет `src/app/instance_config/` — снимок в процессе, загрузка в lifespan **до** приёма трафика, фоновое обновление раз в `ADMIN_OVERRIDES_REFRESH_SECONDS` (новая env, дефолт 30), немедленное обновление в процессе-писателе после коммита, отказ обновления **сохраняет** прежний снимок. Резолверы «оверлей → env → дефолт кода». **Вторая новая env** — `ADMIN_ECONOMICS_RATE_LIMIT_PER_MIN` (дефолт **120**) + функция `enforce_admin_economics_limits(ip=…)` с корзиной `rl:admin_econ:{ip}` ([§10.1](../../adr/ADR-099-crm-admin-economics-and-instance-settings.md)). Обе переменные обязаны **отсутствовать** в существующих `.env` — иначе выкат потребует ручной правки 41 файла. | ADM-3 |
| ADM-13 | **Реестры строк**: тарифные строки из реестра моделей fal и каталога chat-моделей (`tariff_id` по схеме [§3](../../adr/ADR-099-crm-admin-economics-and-instance-settings.md)), дефолты **вычисляются** `run_price()`/`CHAT_CREDIT_COST_GENERAL`; каталог продуктов — слияние пяти источников; реестр 14 настроек с `type`/`options`/`constraints`. | ADM-12 |
