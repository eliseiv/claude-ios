# Documents — Overview

## Назначение
Персистентный **текстовый** документ, привязанный к чату: модель составляет его инструментом `document.create`, дорабатывает `document.update`, приложение показывает и скачивает по REST. Решение — [ADR-090](../../adr/ADR-090-chat-documents.md); проекция изменений в ответ хода — [ADR-101](../../adr/ADR-101-chat-response-documents.md).

## Разведение с четырьмя соседями (все четыре — не то же самое)
| Что | Кто пишет | Где исполняется / живёт | Почему это не документ |
|---|---|---|---|
| `files.*` (`read`/`write`/`list`/`mkdir`, + code-tools [ADR-094](../../adr/ADR-094-code-assistant-tools.md)) | модель | **устройство пользователя** (client-side) | бэкенда не касается; одноимённость по смыслу — ловушка |
| `site.*` ([ADR-011](../../adr/ADR-011-server-side-tools.md)) | модель | `site_files`, отдаётся preview-роутом | результат — HTML-сайт, а не документ |
| Вложения `attachments[]` ([ADR-020](../../adr/ADR-020-inline-base64-attachments-mvp.md)) | пользователь | контекст хода | не персистятся, изменению не подлежат |
| Файлы-знания workspace ([ADR-036](../../adr/ADR-036-workspaces-implementation.md)) | пользователь | `workspace_files`, контекст проекта | наружу отдаются только метаданные; модель их не меняет |

## Scope
- REST: `POST` / `GET` (список) / `GET {documentId}` (с содержимым) / `PATCH {documentId}` / `DELETE {documentId}` / `GET {documentId}/download` под префиксом `/v1/chats/{sessionId}/documents`.
- Global server-side tools: `document.create`, `document.list`, `document.read`, `document.update` (исполняет backend в tool-loop, без round-trip к клиенту).
- Осведомлённость модели: строка со списком `filename (id=…)` в системном промте, когда в сессии есть хотя бы один документ.
- Лимиты на сессию: размер одного документа, число документов, суммарный размер, срез строки промта.
- Проекция изменений хода в ответ генерации — поле `documents[]` ([ADR-101](../../adr/ADR-101-chat-response-documents.md); **код написан, автотестами не покрыт, ревью не проходило, в `main` не слит и не выкачен**).

## Out of scope
- Бинарные форматы и рендер в PDF/docx на выходе ([Q-090-1](../../99-open-questions.md)).
- Патч-семантика обновления (диапазон строк / replace-подстрока) — отвергнута [ADR-090 §3](../../adr/ADR-090-chat-documents.md).
- Оптимистическая конкурентность (`If-Match`, `409 conflict`) — `version` для неё не используется, см. [02-api-contracts.md §version](02-api-contracts.md#version--признак-изменения-а-не-механизм-конкурентности).
- Совместный доступ, шеринг, перенос документа в другой чат, восстановление после удаления чата.
- Object storage — текст ≤ 256 KiB хранится в колонке, как `site_files`/`workspace_files` ([TD-009](../../100-known-tech-debt.md)).
- Модерация содержимого — не применяется по предикату [ADR-086 §2](../../adr/ADR-086-ugc-moderation.md), см. [BR-DOC-8](#бизнес-правила).
- Per-instance выключатель семейства — не заводится ([ADR-090 §3](../../adr/ADR-090-chat-documents.md), проверка в [03-architecture.md §Гейты](03-architecture.md#гейты-которых-нет)).

## Бизнес-правила
- **BR-DOC-1.** Документ принадлежит паре (владелец, сессия). Чужой и несуществующий неотличимы — оба дают `404`, чтобы существование чужого объекта не раскрывалось.
- **BR-DOC-2.** Скоуп — чат: удаление чата удаляет документы (`ON DELETE CASCADE`). Это следствие выбранного скоупа, а не оптимизация; клиент обязан предупреждать при удалении чата с документами ([ADR-090 §2](../../adr/ADR-090-chat-documents.md)).
- **BR-DOC-3.** Обновление — **полная замена** содержимого. Патча нет ни в REST (`PATCH` — только транспортный глагол), ни в инструменте.
- **BR-DOC-4.** `version` растёт на единицу при каждом обновлении и служит **признаком изменения** для UI. В конкурентности не участвует: условной проверки нет, побеждает последняя запись.
- **BR-DOC-5.** `createdBy` (`user` | `assistant`) — факт **происхождения** для отображения. На права не влияет: модель правит документ, загруженный пользователем, и наоборот.
- **BR-DOC-6.** Скачивание идёт под тем же `Authorization`, что и остальные `/v1/*`. Подписанного URL нет — правило медиа ([ADR-085](../../adr/ADR-085-media-asset-download-proxy.md)) сюда **не переносится**.
- **BR-DOC-7.** Ограничение частоты применяется ко **всем** маршрутам модуля, включая скачивание.
- **BR-DOC-8.** Модерация не применяется: документ не рендерится приложением как медиа и не становится промптом или референсом платной генерации — оба критерия [ADR-086 §2](../../adr/ADR-086-ugc-moderation.md) дают «нет». Если документ когда-нибудь начнёт уходить в генерацию, вердикт пересматривается вместе с этим изменением.
- **BR-DOC-9.** Биллинг неизменен ([ADR-006](../../adr/ADR-006-credit-billing-and-subscription-grant.md)): REST-операции с документами бесплатны, server-side раунды `document.*` кредитов не списывают, ход чата тарифицируется как обычно.
