# ADR-060 — Генерация фото и видео через fal.ai: очередь задач вместо синхронного ответа

- Статус: Accepted (§4 «Биллинг» пересмотрен [ADR-061](ADR-061-fal-price-calibration-and-priced-defaults.md) 2026-08-05: цены видео подняты до двукратного покрытия закупки, влияющие на цену параметры получили серверные дефолты; граница «ассеты не проксируются» пересмотрена [ADR-085](ADR-085-media-asset-download-proxy.md) 2026-08-21: клиенту — signed URL на `SERVICE_DOMAIN`, байты стримятся с fal, в БД остаётся fal CDN; тело этого ADR не переписано — immutability)
- Дата: 2026-08-04
- Тип: feature-ADR (новый модуль [media-generation](../modules/media-generation/README.md))
- Связано: [ADR-005](ADR-005-idempotency-ledger.md) (идемпотентность ledger — ключ списания/возврата), [ADR-015](ADR-015-consumable-token-iap.md) (anti-tamper BR-TP-1 — цена только с сервера), [ADR-051](ADR-051-cloudpayments-checkout-payment-link.md) (паттерн исходящего httpx-клиента: таймаут, маппинг ошибок в `502` без утечки upstream), [ADR-033](ADR-033-llm-provider-abstraction.md) (провайдер LLM — **не** затронут: генерация медиа идёт мимо chat-оркестратора)

## Context

Продукту нужна генерация изображений и видео. Сейчас её нет: инструменты tool-loop работают с текстом и файлами, а изображения ходят только **на вход** (vision, [ADR-020](ADR-020-inline-base64-attachments-mvp.md)). Ни одного эндпоинта, который бы что-то генерировал, в API нет.

Выбран провайдер **fal.ai** и пять моделей: Nano Banana Pro, Nano Banana 2, Kling Video, Kling Video V3, Veo 3.1. У этого набора три свойства, которые определяют дизайн:

1. **Время генерации несовместимо с синхронным HTTP.** Изображения у Nano Banana — секунды, но Kling и Veo считают **минутами**. Синхронный эндпоинт означал бы запрос, висящий 2–5 минут: его срежет reverse-proxy, iOS-таймаут и любой мобильный роуминг. У fal ровно для этого есть queue API (`https://queue.fal.run`): `POST` возвращает `request_id` немедленно, статус и результат забираются отдельными `GET`.
2. **Входные схемы моделей несовместимы между собой, и fal отбивает лишние ключи.** У Veo нет `negative_prompt`, у Kling нет `resolution`, `num_images` есть только у image-моделей. Хуже: имя поля со референсным изображением **не унифицировано** — image-модели берут список `image_urls`, Kling v2.5 и Veo берут `image_url`, а Kling v3 image-to-video берёт `start_image_url`. Прямой проксирование тела клиента к fal дало бы поток `422` на каждой второй комбинации.
3. **Каждый запуск стоит реальных денег** у провайдера, причём Veo дороже Nano Banana на порядок. Значит нужна цена в кредитах, и она обязана быть серверной.

## Decision

**Новый модуль `src/app/media_generation/` и пять JWT-защищённых эндпоинтов под тегом `Media`:** `GET /v1/media/models`, `POST /v1/media/images`, `POST /v1/media/videos`, `GET /v1/media/jobs`, `GET /v1/media/jobs/{jobId}`. Контракт — в [media-generation/02-api-contracts.md](../modules/media-generation/02-api-contracts.md).

### 1. Асинхронный контракт: `202` + задача, опрос вместо ожидания

`POST /v1/media/images|videos` ставит запуск в очередь fal и отвечает **`202`** с задачей в статусе `queued`. Клиент опрашивает `GET /v1/media/jobs/{jobId}` до `completed` (ссылки в `assets`) или `failed` (причина в `error`).

Опрос, а не вебхук: fal умеет колбэк (`fal_webhook`), но он потребовал бы публичной callback-поверхности и схемы подписи — то есть ровно того класса задач, где у нас уже были инциденты с потерянными платежами ([ADR-054](ADR-054-cloudpayments-webhook-payment-verification.md)). Опрос не добавляет ни одного неаутентифицированного эндпоинта, а iOS-клиент уже устроен как поллер.

**Опрашивает только `GET /v1/media/jobs/{jobId}`.** Список `GET /v1/media/jobs` — read-only: N задач в списке не должны превращаться в N исходящих вызовов, поэтому у незавершённых задач отдаётся последнее известное состояние. После терминального статуса (`completed`/`failed`) ответ идёт из БД — провайдер больше не дёргается.

### 2. Реестр моделей на сервере, а не идентификаторы fal у клиента

`media_generation/catalog.py` — единственный источник истины. Клиент присылает короткий стабильный id (`nano-banana-2`, `veo-3.1`), сервер разрешает его в endpoint fal. У каждой модели **два варианта**: prompt-only и «с референсным изображением» — это разные endpoint'ы у fal (`fal-ai/nano-banana-2` против `fal-ai/nano-banana-2/edit`, `…/text-to-video` против `…/image-to-video`).

Каждый вариант объявляет **allowlist полей**, которые уходят наверх; всё остальное отбрасывается, а не проксируется (см. Context §2). Асимметрия имени поля с картинкой (`image_urls` / `image_url` / `start_image_url`) живёт здесь же, поэтому схемы и сервис остаются модель-агностичными.

**Наборы допустимых значений живут на варианте, а не на модели.** Сверка с опубликованными схемами fal (`fal.ai/api/openapi/queue/openapi.json?endpoint_id=…`) показала, что они различаются между режимами одной модели: у Veo text-to-video `aspect_ratio` не принимает `auto`, а image-to-video принимает; Kling в image-to-video не принимает `aspect_ratio` вовсе (берёт из стартового кадра). Хранение наборов на модели давало бы ложные разрешения в одном режиме и ложные запреты в другом.

Валидация значений на нашей стороне — не дублирование чужой проверки, а необходимость: **fal не валидирует enum на сабмите.** Живой прогон показал, что запрос с `resolution: "512x512"` получает `200` и request id (кредиты уже списаны), доходит до статуса `COMPLETED`, а response URL навсегда отвечает `422 literal_error`. Значит расхождение со схемой провайдера проявляется не отказом сабмита, а оплаченным запуском без результата. Реестр сверяется со схемами скриптом `tests/e2e_live/verify_fal_catalog.py` (сетевой, вне `make ci`).

Отсюда форма `GET /v1/media/models`: модель отдаёт `modes[]`, где у каждого режима свои `params` (какие поля он принимает) и свои наборы значений. Клиент строит контролы по режиму; пустой список = параметра в этом режиме нет. Значит смена модели, набора значений или цены не требует релиза iOS.

Экспонируется **подмножество** входа fal. Не отдаются наружу `safety_tolerance` и `system_prompt` (ослабление модерации и инъекция системного промта — не параметры генерации) и `sync_mode` (сломал бы очередь, на которой построен весь модуль).

### 3. Исходящий клиент: паттерн ADR-051

`media_generation/fal_client.py` — тонкий httpx-клиент (`submit`/`status`/`result`), по образцу [ADR-051](ADR-051-cloudpayments-checkout-payment-link.md): per-call `AsyncClient`, таймаут из конфига, ключ в **своей** схеме fal `Authorization: Key <FAL_API_KEY>` (не `Bearer`), ключ не логируется.

Маппинг ошибок:

| upstream | наш ответ | почему |
|---|---|---|
| таймаут / connect / не-2xx / битый JSON | `502 upstream_error` | провайдер недоступен; тело/статус наверх не проксируем |
| `401`/`403` | `503 media_generation_not_configured` | отбитый ключ — проблема **оператора**, а не клиента; отличима от аварии fal |
| `422` **на сабмите** | `422 validation_error` с текстом fal | единственное исключение из «не проксировать»: сообщение fal называет проблемный параметр, секретов не содержит, и это ровно то, что нужно клиенту. Текст обрезается до 500 символов и сплющивается в одну строку |
| `422` **на опросе** | `200` со `status: failed` + возврат кредитов, текст fal в `error` | часть входа fal валидирует только в момент исполнения (например, недостижимую ссылку на картинку) и затем **навсегда** отдаёт этот вердикт из status/response URL. Пробросить `422` значило бы ответить кодом валидации на корректный `GET`, оставить задачу нетерминальной насовсем и никогда не вернуть кредиты. Найдено живым прогоном ADR-060, см. §Тесты |
| `429` | `429 rate_limited` | лимит провайдера |

Различие в последних двух строках существенно: на сабмите задачи ещё нет и `422` адресован телу запроса, а на опросе `422` — это уже исход **принятого** запуска, то есть провал, а не проблема опроса. Транзиентные ошибки (`429`/`502`) на опросе по-прежнему пробрасываются: они не вердикт по запуску, задача остаётся нетерминальной, и следующий опрос доберёт исход.

URL'ы опроса (`status_url`/`response_url`) **берутся из ответа fal и персистятся**: для вложенных endpoint'ов вида `kling-video/v3/pro/text-to-video` очередная тропа не выводится из одного id. Так как это URL от внешней системы, перед каждым запросом проверяется префикс `FAL_QUEUE_BASE` (SSRF-guard); не прошёл — падаем в канонический вид, а не идём по чужому хосту.

### 4. Биллинг: списание при постановке, возврат при провале, одна транзакция

Базовая цена — `catalog.default_credits`, переопределяемая оператором через `MEDIA_MODEL_CREDITS` (JSON `{modelId: credits}`). В теле запроса **поля цены нет вообще** (anti-tamper, симметрия BR-TP-1 [ADR-015](ADR-015-consumable-token-iap.md)); неположительный override отбрасывается парсером, поэтому опечатка не может сделать запуск бесплатным.

**Цена масштабируется объёмом выпуска**, потому что так же считает fal: за каждое изображение и за каждую секунду видео. Итог = базовая цена × `numImages` для изображений и × `ceil(duration / base_duration_seconds)` для видео (`base_duration_seconds` — 5 у Kling, 8 у Veo). Без множителя самые дорогие для нас опции оказались бы самыми дешёвыми для пользователя: 4 изображения или 15-секундный клип стоили бы столько же, сколько одно изображение и 5 секунд, — то есть открытие `numImages` и длинных `duration` прямо создавало бы убыток. Множитель округляется вверх и не бывает меньше 1, поэтому клип короче базовой длительности не становится бесплатным. Баланс проверяется по **итоговой** цене, так что слишком длинный запрос при малом балансе — `409` до списания, а не наполовину оплаченный запуск.

Порядок: `wallet.consume` → `fal.submit` → `INSERT media_jobs`, всё в **одной** request-транзакции (`session_scope`). Отсюда два инварианта:

- **Сабмит упал → списание откатилось.** Пользователь не платит за запуск, который fal не принял.
- **Строка `media_jobs` существует ⇒ за неё заплачено и fal ею владеет.**

Ключ идемпотентности — `media-gen:{jobId}`, поэтому **`jobId` генерируется в Python, а не дефолтом БД**: списание должно быть атрибутируемо к задаче раньше, чем появится строка.

**Провал у провайдера возвращает кредиты** (`media-refund:{jobId}`, `wallet.grant`): пользователь заплатил за результат, которого не получил. Возврат идемпотентен дважды — ключом ledger ([ADR-005](ADR-005-idempotency-ledger.md)) и флагом `credits_refunded`. `COMPLETED` без пригодного URL трактуется как провал: с точки зрения пользователя разницы нет.

### 5. Гейт активации и данные

`FAL_API_KEY` пуст → вся поверхность `/v1/media/*` отвечает `503 media_generation_not_configured`, **включая каталог моделей**: инстанс без ключа не может выполнить ни одну модель, и отдавать по нему справочник значит предлагать клиенту нарисовать выбор моделей, ни одна из которых не запустится. Единый ответ на всём префиксе даёт клиенту скрыть раздел генерации по одному вызову, а не узнавать об отключённой фиче после того, как пользователь выбрал модель. Фича включается **по инстансу**, как RU-checkout ([ADR-051 §5](ADR-051-cloudpayments-checkout-payment-link.md)).

Новая таблица `media_jobs` (**миграция `0018`**, down_revision `0017_subscription_will_renew`, single head): владелец, id модели, endpoint fal, `fal_request_id` + два URL опроса, статус, списанные кредиты, флаг возврата, нормализованный результат. `status` — `TEXT` + `CHECK`, а не новый enum: набор значений повторяет lifecycle очереди fal (внешний контракт), и его расширение не должно требовать `CREATE TYPE` на каждом инстансе. Индекс `(user_id, created_at)` под листинг.

Результат нормализуется на границе в стабильную форму `{assets: [{url, contentType, fileName}]}` — image-модели возвращают `images[]`, video-модели одиночный `video`. Вендорные имена полей не попадают ни в БД, ни к клиенту.

### Границы

Генерация медиа **не проходит** через chat-оркестратор: ни инструмента tool-loop, ни шага в `chat_steps`, ни зависимости от `LLM_PROVIDER` ([ADR-033](ADR-033-llm-provider-abstraction.md)). Ассеты не проксируются и не перекладываются в наше хранилище — отдаются ссылки CDN fal (срок жизни ссылок на стороне провайдера — [Q-060-1](../99-open-questions.md)). Подписка не требуется: гейт — только баланс кредитов.

## Consequences

- (+) Минутные видео-генерации работают, не упираясь в таймаут proxy/клиента.
- (+) Добавление модели или смена цены — правка реестра/env, без релиза iOS: клиент читает `GET /v1/media/models`.
- (+) Пользователь не платит за запуск, который провайдер не принял или провалил.
- (+) Идентификаторы и входные схемы fal не протекают в контракт — провайдера можно заменить, не меняя `/v1/media/*`.
- (+) Параметры (разрешение, длительность, соотношение сторон, звук, `cfgScale`, `seed`) доступны клиенту с описанием допустимых значений **по режимам**, поэтому UI не гадает и не платит за upstream-отказы.
- (−) Цена одного запуска больше не константа модели: она зависит от `numImages`/`duration`. UI должен считать её сам перед запуском (данных из каталога для этого достаточно) и в любом случае показывать `creditsCharged` из ответа как факт.
- (−) Клиент обязан опрашивать: результат не приходит одним ответом. Смягчено `202` + явными статусами.
- (−) Незавершённая задача, которую никто не опрашивает, остаётся `queued`/`running` навсегда (нет фонового реконсилятора) — кредиты за такую тихо провалившуюся генерацию не вернутся, пока клиент не сходит за статусом. Фоновая доводка — [Q-060-2](../99-open-questions.md).
- (−) Цены в кредитах выставлены оценочно и требуют калибровки под реальный биллинг fal — [Q-060-3](../99-open-questions.md).
- Миграция `0018`; новые env `FAL_API_KEY`/`FAL_QUEUE_BASE`/`FAL_TIMEOUT_SECONDS`/`MEDIA_MODEL_CREDITS`/`MEDIA_JOBS_PAGE_LIMIT`. Существующие флоу (chat, биллинг, BYOK, workspaces) не затронуты.

## Тесты

- `tests/unit/test_media_catalog_adr060.py` — состав реестра и стабильность публичных id; endpoint'ы совпадают с id моделей fal; имя поля с картинкой per-family (включая `start_image_url` у Kling v3); проекция запроса в input fal отбрасывает `None` и неподдерживаемые полем варианта ключи; наборы значений совпадают с опубликованными enum'ами fal (`0.5K` у nano-banana-2, `4k` у Veo, `3`…`15` у Kling V3) и различаются по режимам (`auto` у Veo только с картинкой, у Kling image-to-video `aspectRatio` отсутствует); множитель цены по `numImages` и длительности (округление вверх, минимум 1, нераспознанная длительность → базовая цена).
- `tests/unit/test_media_generation_units_adr060.py` — парсинг `MEDIA_MODEL_CREDITS` (кривой JSON / не-объект / `0` / отрицательное / `bool` / строка → override отбрасывается), приоритет override над дефолтом, отсутствие поля цены в схемах запроса, нормализация результата image/video.
- `tests/unit/test_media_schemas_adr060.py` — `extra=forbid`, пустые `model`/`prompt`, лимиты, allowlist схемы URL (`http`/`file`/`data`/protocol-relative → `422`).
- `tests/integration/test_media_generation_adr060.py` — полный HTTP-путь с фейком на границе httpx: каталог с серверной ценой и override; каталог отдаёт режимы с их `params` и наборами значений; масштабирование цены (`numImages: 4` → ×4, `duration: "15"` → ×3) и `409` по итоговой цене; проброс `cfgScale`/`seed`/`negativePrompt` только тем моделям, которые их принимают; `aspectRatio: "auto"` отбит для Veo text-to-video и принят с картинкой; контракт сабмита (URL очереди, snake_case-поля, `Authorization: Key`); выбор edit/image-to-video endpoint; `422` до списания (неизвестная модель, модель не того типа, неподдерживаемое значение/параметр); `409` без кредитов; откат списания при `502`/таймауте; `503` на `401` от fal и на незаданном ключе; `422` с проброшенным именем параметра; опрос `running`/`completed`/`failed`; `422` от status/response URL при опросе → терминальный `failed` с возвратом, а `502` при опросе оставляет задачу опрашиваемой; возврат кредитов ровно один раз; терминальная задача отдаётся из БД без повторного вызова; листинг newest-first без опроса + фильтр `kind`; изоляция владельца (`404`) и `401` на всех маршрутах.

**Живой прогон против fal (2026-08-04, локальный стек, реальный ключ).** Все пять моделей дошли до `completed` с пригодными ассетами — как в text-only, так и с референсной картинкой (`nano-banana-pro/edit`, `kling-video/v2.5-turbo/pro/image-to-video`, `kling-video/v3/pro/image-to-video`): изображения 13–20 с, видео 90–100 с. Подтверждено: серверные цены списываются ровно (`4/8/120/200/300`), отказы валидации бесплатны, изоляция владельца и `401` работают, ключ не появляется ни в логах, ни в БД. Опрос вернул реальные URL опроса от fal вида `fal-ai/kling-video/requests/{id}` — без вложенного пути endpoint'а, что и было причиной их персиста. **Прогон нашёл дефект, исправленный этим же ADR:** запуск с недостижимой картинкой fal помечает `COMPLETED`, но отдаёт `422` из response URL — задача навсегда застревала нетерминальной, на каждый опрос уходил `422`, кредиты не возвращались (см. §3, строка «`422` на опросе»).
