# ADR-059 — Системный промпт декларирует наличие памяти диалога

- Статус: Accepted
- Дата: 2026-07-28
- Тип: bugfix-ADR, **расширяет [ADR-012](ADR-012-assistant-mode-vs-billing-mode.md)** (базовый системный промпт по `assistant_mode`); тот же паттерн статичной инструкции, что [ADR-026 §7](ADR-026-global-server-side-tools-and-time-now.md) (`_TIME_NOW_INSTRUCTION`).
- Связано: [ADR-033](ADR-033-llm-provider-abstraction.md) (провайдер по env; на проверенных инстансах активен `openai`/gpt-4o), [ADR-036 §3](ADR-036-workspaces-implementation.md) (workspace-инструкции добавляются ПОСЛЕ базового промпта). Модуль [chat-orchestrator](../modules/chat-orchestrator/README.md).

## Context

**Инцидент (прод novirell, воспроизведён): модель отвечает, что «не может запоминать», хотя история диалога до неё доходит.**

Переписка тестера (подписка активна):

```
тестер:  Запомни число 345
ИИ:      Я не могу хранить данные, но всегда могу помочь…
тестер:  Какое число я писала?
ИИ:      Извините, я не могу запоминать информацию. Вы упомянули число 345 ранее.

тестер:  Remember the codeword ORBIT. Reply only ACK
ИИ:      ACK
тестер:  What's the codeword?
ИИ:      I'm sorry, I can't disclose any stored information.
```

**Это не потеря контекста.** `_build_messages` (`orchestrator.py`) на каждом ходе перечитывает **все** шаги сессии и отдаёт их провайдеру — история реплеится. Прямое доказательство — в самом транскрипте: во втором ответе модель **сама называет «345»**, т.е. предыдущие ходы у неё в контексте. Реплей подтверждён и на живом novirell (`sessionId` переиспользован → шаги `['user','assistant',…]`).

**Корень — формулировка ответа модели, а не отсутствие данных.** Активный провайдер на инстансе — `openai`/gpt-4o ([ADR-033](ADR-033-llm-provider-abstraction.md)). Слово «запомни/remember» gpt-4o по умолчанию трактует как просьбу о **межсессионном постоянном хранении** и выдаёт шаблонный дисклеймер «я не могу хранить/запоминать», хотя в пределах диалога факт у неё есть (вспомнила 345, ответила `ACK` на ORBIT). Наш базовый системный промпт ([ADR-012](ADR-012-assistant-mode-vs-billing-mode.md)) при этом **нигде не сообщает модели, что у неё есть вся история диалога** — пустое место, которое модель заполняет своим дефолтным «я без памяти».

Не воспроизводится как «нет памяти» только при двух условиях (оба — на стороне клиента/биллинга, не в этом ADR): клиент обязан переиспользовать `sessionId` в последующих сообщениях (без него каждый запрос — новая сессия без истории); триал-юзер получает одну бесплатную генерацию ([ADR-002](ADR-002-access-policy-state-machine.md)), второе сообщение без подписки блокируется `trial_used`.

## Decision

**Добавить в базовый системный промпт статичную инструкцию `_CONVERSATION_MEMORY_INSTRUCTION`** — в оба режима (`chat`/`code`), рядом с `_TIME_NOW_INSTRUCTION`:

> "You have access to the full history of the current conversation; earlier messages in this chat are part of your context. When the user asks you to remember something or refers back to what was said, use that history to answer directly. Never claim you cannot remember, store, or recall information from this conversation."

Обоснование:

- **Бьёт точно в корень.** Прошлые `chat_steps` — и есть память; инструкция говорит модели трактовать их как память и прямо запрещает дисклеймер о statelessness. Данные уже доходили — меняется только поведение при ответе.
- **Статична — кэш не ломается.** Никакой интерполяции per-request, поэтому префикс системного промпта стабилен и Anthropic prompt-cache (`cache_control: ephemeral`) не инвалидируется — тот же инвариант, что у [ADR-026 §7](ADR-026-global-server-side-tools-and-time-now.md).
- **Провайдер-нейтральна.** Формулировка помогает gpt-4o (где баг воспроизведён) и безвредна для Anthropic-инстансов; знание о конкретном провайдере в промпт не зашивается.
- **Совместима с workspace.** `_system_prompt_with_workspace` добавляет инструкции проекта ПОСЛЕ базового промпта ([ADR-036 §3](ADR-036-workspaces-implementation.md)) — порядок сохранён, memory-строка попадает в базу.

**Границы:** только текст системного промпта. Реплей истории, набор инструментов, биллинг, `assistant_mode`-развилка и контракт не меняются. Не адресует расхождение `INSTANCES`/провайдера с доками (novirell в доках нет; на проверенных инстансах активен gpt-4o вопреки описанию Claude) — это отдельный операторский вопрос.

**Альтернатива — сменить провайдер на Anthropic — отвергнута** как решение этого бага: дисклеймер о памяти — свойство формулировки, а не тира модели; правка промпта дешевле, деплоится тем же релизом и не завязана на смену `LLM_PROVIDER`.

## Consequences

- (+) На «запомни X» + последующий вопрос модель отвечает из истории, без «я не могу запоминать».
- (+) Один источник истины для обоих режимов; поведение одинаково на любом провайдере.
- (−) Промпт длиннее на одно предложение (пренебрежимо для контекста и кэша).
- Без миграции, без env, контракт API не меняется.

## Тесты

`tests/unit/test_system_prompt_memory_adr059.py` — инструкция присутствует в обоих режимах; содержит формулировки «full history…» и «never claim you cannot remember»; статична (нет `{`-интерполяции); workspace-инструкции по-прежнему добавляются после базы.
